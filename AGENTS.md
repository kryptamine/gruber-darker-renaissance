# AGENTS.md

Gruber Darker Renaissance — a dark Neovim colorscheme, written in Lua. No
dependencies and no build step: Neovim loads it straight from the runtime path.

## Repository layout

```
colors/gruber-darker-renaissance.lua  the :colorscheme entry point
lua/gruber-darker-renaissance/
  init.lua      setup() and load()
  config.lua    options and their defaults
  palette.lua   raw colors, the only place a hex value is written
  colors.lua    semantic colors built from the palette
  terminal.lua  :terminal colors
  extras/       one renderer per tool, written to extras/ by make extras
  groups/       highlight groups, one module per area
    plugins/    one module per plugin integration
lua/lualine/themes/  the lualine theme, built from the semantic colors
extras/         generated themes for other tools, never edited by hand
queries/        tree-sitter query extensions, only where a group cannot do it
assets/         README images
scripts/        the headless smoke test and the extras generator
```

Every group module exports `get(colors, opts)` and returns a table of groups; a
string value is a link. README's "Structure" says the rest.

## Language rule (mandatory)

**Everything written into this repository is in English.** Code comments, commit
messages, documentation, test names, ticket text — all English, with no
exceptions. This holds regardless of the language the request was made in; only
the conversation with the user follows the user's language.

## Commit convention (mandatory)

Commits follow [Conventional Commits](https://www.conventionalcommits.org):

```
<type>(<optional scope>): <subject>

<optional body explaining why, wrapped at 72 columns>
```

Types in use: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `chore`.
Scope is an area (`palette`, `editor`, `syntax`, `treesitter`, `lsp`, `config`)
or a plugin integration (`blink`, `fzf`, `gitsigns`).

- Subject in the imperative mood, lowercase, no trailing period, ≤72 characters
  ("add oil integration", not "Added oil integration.").
- The body explains why, not what — the diff already says what.
- One logical change per commit.
- **Never add a co-author trailer or any other attribution** — no
  `Co-Authored-By`, no "Generated with" line, in a commit or a pull request.

## Branches and pull requests (mandatory)

**Never commit to `main`.** Branch from it first, named `<type>/<kebab-summary>`
with the types the commits use: `feat/oil-integration`, `fix/float-border`,
`refactor/semantic-colors`.

- **Pull requests are merged by rebase**, never squashed or merged, so each
  commit message is what lands in the history.
- Keep a pull request to one thing. A palette change, a new integration and a
  formatting sweep are three pull requests.
- **A pull request body follows
  [.github/pull_request_template.md](.github/pull_request_template.md)**:
  Summary, Evidence, Merge Danger and the checklist, every section filled and
  no attribution line. How to fill each section is in
  [.claude/skills/pr/SKILL.md](.claude/skills/pr/SKILL.md), for any agent.

## Color rule (mandatory)

**A hex value is written only in `palette.lua`.** Groups take semantic colors
from `colors.lua` (`c.syntax.keyword`, `c.diag.error`, `c.bg_float`) and fall
back to a palette name only for a one-off accent. A color that two groups agree
on gets a semantic name, so changing it is one edit.

`extras/` is the one exception: it is generated by `make extras` from the palette
and never edited by hand.

## Group rule (mandatory)

**A group exists only if something renders it.** A plugin integration lands
only for a plugin in use, and covers only groups whose defaults do not already
follow the theme — a plugin that links to `Directory` or `DiagnosticWarn`
needs nothing. Delete an integration the moment its plugin goes.

## Comment rule (mandatory)

**A comment is at most three lines**, and it says what is surprising rather than
what is visible. The rule in full, with worked examples, is in
[.claude/rules/comments.md](.claude/rules/comments.md).

## Commands

```sh
make            # list every target
make check      # fmt + lint + smoke   ← the gate before any commit
make fmt        # stylua
make smoke      # load the theme headless, fail on an unresolved link
make extras     # regenerate extras/ (fish, ghostty, herdr, lazygit) from the palette
```

Inside Neovim, `:ThemeReload` (defined in the user's config, not here) reloads
the theme from disk without a restart.

## Working here

- The user runs this theme from this checkout: their Neovim config loads it
  with `dir = "~/Work/gruber-darker-renaissance"`. A broken load breaks their
  editor, so `make check` before handing work back.
- **Check what a group renders as, not what it is set to.** Neovim's default
  colorscheme defines most groups, so a group the theme leaves out still has a
  color. Compare `nvim_get_hl(0, { name = ..., link = false })` before and
  after a change.
- Tree-sitter captures use the current names (`@variable.member`,
  `@keyword.conditional`, `@markup.*`). The old ones (`@field`, `@conditional`,
  `@text.*`) are no longer emitted and a group set on them renders nothing.
- An empty semantic-token group (`["@lsp.type.variable"] = {}`) is deliberate:
  it adds no attributes, so tree-sitter's finer highlight shows through.
